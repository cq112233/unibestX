# UI 库替换篇

UI 库替换优先通过**切换模板分支**完成，不建议在已有业务项目里手工把两套组件库互相覆盖。

## 推荐流程

1. 先确定目标库：Rice UI / uview-ultra / 无 UI 库。
2. 从对应分支创建干净项目。
3. 把业务页面、接口层和静态资源迁移过去。
4. 逐个替换 UI 组件，保留原有业务逻辑与数据结构。
5. 跑 `pnpm health`、`pnpm typecheck`、`pnpm lint` 和至少一个原生端编译。

```bash
npx degit cq112233/unibestX#uniX-rice-ui my-app
cd my-app
pnpm install
pnpm dev:web
```

## 迁移原则

- 一次只替换一个业务模块，不要全仓批量改名。
- 先把主题、间距、圆角、字号映射到目标库令牌。
- 页面 URL、路由名和接口函数签名保持不变。
- 自定义组件优先保留业务语义，只替换内部 UI 实现。
- 原生 TabBar 图标与 UI 库图标是两套资源，不要混用。

## 风险检查

- 目标库是否支持 Vapor 与 VDOM。
- 是否存在平台专属组件，例如签名、扫码、文件预览。
- 是否引入原生插件，是否需要自定义基座。
- 是否影响包体积与小程序主包预算。
